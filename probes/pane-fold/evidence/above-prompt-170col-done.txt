  Cache Design (cache.txt)

  This design implements a fixed-capacity cache of 100 entries using Least Recently Used (LRU) eviction. The strategy is straightforward: when capacity is reached, the
  entry not accessed for the longest time is discarded. LRU is a pragmatic choice balancing simplicity with effectiveness. It assumes temporal locality—recent accesses
  predict near-future accesses—a reasonable heuristic for many workloads. The fixed capacity trades flexibility for predictability; memory consumption never exceeds
  bounds, aiding resource planning.

  However, LRU's weakness is insensitivity to access frequency: an entry accessed once then ignored forever may evict a frequently accessed entry if older. The 100-entry
  limit assumes this threshold suits the expected working set; too small and thrashing occurs, too large and memory is wasted. This design shines in workloads with strong
  temporal locality but struggles with bursty access patterns or bimodal frequencies. No warmup or adaptive sizing mechanism is mentioned, suggesting a static,
  fire-and-forget approach suitable for predictable, stable access patterns rather than dynamic or heterogeneous demand.

  This parser employs a line-delimited, comma-separated values approach—a deliberate simplicity that prioritizes straightforward field extraction over robustness. By

  leading/trailing whitespace, a pragmatic choice that handles casual formatting inconsistencies. The design is intentionally lossy: no escaping recovery, no column
